# P1.3c.4: online seal, representative, generation and readback

P1.3c.4 runs 33 native positions. Position 511 establishes the first argmax;
positions 512–543 generate a real 32-token per-layer tail. Every step uses
native embedding feedback, 28-layer Q/K/V sparse execution and LM head.

At tail=32 the native sealer consumes all real queries and FP16 K/V, accumulates
local-causal attention mass per query head, selects `repr_topk=4`, writes block
ID 16, calls `fsync`, verifies it through fixed-buffer liburing, then publishes
generation 1 with an atomic manifest rename. The rename is the crash-consistent
visibility boundary; 128 KiB `pwrite` itself is not claimed hardware-atomic.

The selection audit ranks the new block as a physical candidate and reads that
offset. The original 16 prompt representatives are not yet merged, so 28/28 is
not an oracle-recall or competition-quality claim. P1.3c.5 must merge both
representative sets and execute history miss correction.
