# P1.2b: real Qwen layer consuming selected SSD KV

P1.2b joins the two previously separate proofs:

- P1.1 native InfLLM selection and physical SSD block transport;
- P1.2a real Qwen3 CUDA/cuBLAS layer execution.

It is the first native path where real post-RoPE Qwen KV is selected in
32-token blocks, read from an SSD file with liburing, copied from pinned DRAM
to VRAM, and consumed by a real Qwen sparse layer.

## Data and selection

- model: `Qwen/Qwen3-0.6B`, layer 0;
- prompt: 512 real embedding vectors, positions 0–511;
- KV: real layer-0 post-RoPE K and real V;
- SSD dtype: FP16;
- layout: `[token, K-or-V, kv_head, head_dim]`;
- block: 32 tokens / 128 KiB;
- selected blocks: `[0, 13, 14, 15]`;
- budget: 128/512 tokens (25%).

Representatives use local causal attention mass with `local_window=32` and
`repr_topk=4` at query-head granularity. The selector query is the real
post-RoPE query at position 511.

## Actual native path

```text
real current hidden
 → RMSNorm → Q projection → Q head norm → RoPE

four selected FP16 KV blocks
 → O_DIRECT/liburing fixed reads
 → CUDA pinned DRAM
 → H2D
 → FP16 interleaved GQA sparse attention

attention result
 → real O projection → residual
 → real post-attention RMSNorm
 → real gate/up/SwiGLU/down projections
 → final residual
```

Sparse mode does **not** recompute the 512 historical K/V projections. An early
P1.2b implementation did so for convenient auditing and measured 3.48 ms. It
was corrected: only the current token's Q path runs, while all historical K/V
must arrive through the SSD store. Native compute then fell to about 1.4 ms.

## Correctness

There are two teachers:

1. PyTorch sparse teacher using the same selected FP16 blocks;
2. PyTorch dense layer using all 512 prompt tokens.

| Comparison | Maximum error | Cosine |
|---|---:|---:|
| native current normalized hidden vs teacher | 0 | 1.0 |
| native post-RoPE Q vs teacher | 1.67310e-4 | 1.0 |
| native sparse attended heads vs sparse teacher | 1.89066e-4 | 0.999999969 |
| native final layer vs sparse teacher | **1.79887e-4** | **0.999999988** |
| sparse final layer vs dense teacher | 3.35624e-2 | 0.999383555 |

The first four values audit implementation fidelity. The final row is sparse
algorithm quality and must not be mixed with implementation error.

## Ten-run timings

| Stage | Median | P10–P90 |
|---|---:|---:|
| four-block O_DIRECT/liburing read | 7.371372 ms | 7.308358–7.521732 ms |
| pinned H2D, 512 KiB | 0.033360 ms | — |
| real current-Q + sparse attention + O/MLP compute | 1.394157 ms | 1.361925–1.472809 ms |

The SSD result is a cold first read in a new process and is unexpectedly much
slower than the earlier persistent P0 ring measurements. It is reported as
observed, not treated as a paper-comparable steady-state number. P1.2c must
retain the process/ring and overlap next-layer reads before drawing throughput
conclusions.
