# P1.0: history prediction and physical miss correction

P1.0 adds the control path that P0 deliberately omitted. Its purpose is to
prove that a stale history prediction can be prefetched, audited against the
current selection, and physically corrected in pinned DRAM and VRAM before
attention.

It still uses controlled synthetic block selections and synthetic QKV/FFN
compute windows. Therefore it is a correction/pipeline validation version, not
yet the real-Qwen selection-quality result. P1.1 will feed the native C2.1
InfLLM representative selector into this exact scheduler.

## Per-layer sequence

```text
previous token's selection
          │
          ├── predicted blocks SSD→DRAM→VRAM (cross-layer P0 pipeline)
          │
current selection ── set difference ── missing blocks
          │                              │
          │             QKV window ──────┼── overlaps correction SSD read
          │                              └── correction block H2D overwrite
          └────────────────────────────────── corrected KV set → attention
```

The scheduler maintains one four-block history set per layer. Init block `0`
and local block `15` remain fixed; two dynamic oracle blocks change every two
decode steps and vary by layer. This controlled drift makes prediction misses
repeatable. The hit metric is actual set intersection:

```text
history_hit_rate = |predicted ∩ oracle| / |predicted|
```

It is not the earlier, invalid “same selection as the previous token” metric.
After replacement, the code reconstructs and sorts the resident set and aborts
unless it exactly equals the oracle set.

## Physical resources

- pinned buffers 0/1: double-buffered four-block predicted batches;
- pinned buffer 2: registered correction batch;
- VRAM slots 0/1: double-buffered attention KV;
- correction H2D copies only missing 128 KiB blocks into evicted slot offsets;
- CUDA compute stream: QKV window, attention and FFN window;
- CUDA copy stream: predicted batch H2D and correction overwrite;
- liburing: both predicted batch and miss-only `O_DIRECT` reads.

## Formal result

RTX 4080 Laptop, 10 repeats, 16 steps × 28 layers/repeat:

| Metric | Result |
|---|---:|
| history block hit rate | 80.6920% |
| predicted blocks / repeat | 1792 |
| corrected miss blocks / repeat | 346 |
| corrected oracle block recall | **100%** |
| serial layer latency, median (P10–P90) | 0.438364 ms (0.422613–0.460522) |
| corrected pipeline latency, median (P10–P90) | 0.399603 ms (0.360172–0.414620) |
| speedup, median (P10–P90) | **1.112365×** (1.088427–1.173459×) |
| correction SSD read / repeat, median | 29.251958 ms |
| correction H2D / repeat, median | 2.944768 ms |
| serial vs corrected output max error | **0** |

P1.0 is slower than P0's 1.383603× because deliberately changing selection
exposes miss I/O. This is expected and useful: a history predictor only helps
to the extent that its hit rate avoids correction traffic.

## Debugging the trace

Open `artifacts/runs/P1.0-history-correction-trace.json` in Perfetto:

- `next-layer KV read`: predicted SSD read;
- `next-layer H2D`: predicted full batch staging;
- `QKV projection window`: current layer compute available to hide correction;
- `selection miss SSD read`: miss-only read into pinned buffer 2;
- `selection correction H2D overwrite`: partial VRAM slot overwrite;
- `selection correction barrier`: exposed correction tail before attention.

The trace is deliberately explicit about the barrier. P1.0 contains no global
`cudaDeviceSynchronize`; it waits only on the QKV and correction events required
by the current layer.
