# P1.3c.1: two-token native feedback plumbing

P1.3c.1 feeds the first native argmax through a native device embedding lookup
and uses that row as the external initial hidden for a second 28-layer pass at
position 512.

```text
chain(position 511) -> LM head -> token 50
token 50 -> native embedding lookup -> chain(position 512) -> token 271
```

## Five-run result

| Metric | Step 0 | Step 1 |
|---|---:|---:|
| token, native / teacher | 50 / 50 | 271 / 271 |
| chain median | 10.151985 ms | 10.145761 ms |
| LM-head median | 2.657970 ms | 2.668187 ms |

| logit cosine | 0.999999999999905 | 0.999999999999902 |

## Critical boundary

The second pass still uses the fixed prompt block plan. Token 50's newly
projected K/V is not yet inserted into attention or selection correction.
Therefore this proves feedback execution and LM-head parity, not correct
continuous sparse decode.

The old chain teacher was generated for the original single-token input. It is
invalid for the external token-50 embedding; raw metrics now mark
`final_reference_valid=false`. Its large stale-reference error must not be used
as a quality result. Per-step LM-head parity is computed from each actual native
hidden and remains valid.
