# P1.3a: generation-safe continuous history correction

P1.3a hardens the existing 16-step history-correction scheduler before it is
connected to real continuous Qwen decode. Every physical prefetch now carries:

```text
token | layer | selection_generation | predicted block set
```

The consumer validates all four fields before attention can use the VRAM slot.
After oracle selection and miss correction, that layer's history generation is
incremented. A buffer that completed successfully at the I/O level can therefore
still be rejected if it belongs to an old token or selection generation.

## Five-run result, 16 steps x 28 layers

| Metric | Median/result |
|---|---:|
| verified tickets per run | **448 / 448** |
| misrouted/stale tickets in normal run | **0** |
| controlled stale-generation self-test | **rejected / passed** |
| history hit rate | 58.5938% |
| miss blocks per run | 742 |
| correction SSD read | 61.050630 ms |
| correction H2D | 5.940128 ms |
| corrected oracle block recall | 1.0 |
| serial/pipeline maximum error | 0.0 |
| pipeline speedup | **0.775908x** |

The slowdown is retained as a result. With this deliberately shifting InfLLM
query fixture, history prediction misses 41.4% of blocks. Miss-only reads and
short synchronization barriers cost more than the overlap saves.

## Scope boundary

This version uses the real CUDA FP16 sparse-attention kernel and physical
liburing correction reads, but its QKV/FFN occupancy windows remain synthetic.
It proves scheduler identity and correction integrity, not real-model
continuous decode quality. The next version must source tickets from real Qwen
per-token selections and add the decode-tail block lifecycle.

## Reproduce

```bash
./scripts/run_cpp_p1_3a.sh --steps 16 --ffn-iterations 512
.venv/bin/python scripts/benchmark_cpp_p0.py \
  --generation-tickets --repeats 5 --steps 16 --ffn-iterations 512
```
