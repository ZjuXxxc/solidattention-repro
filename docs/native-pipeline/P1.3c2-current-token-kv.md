# P1.3c.2: current-token K/V in sparse attention

P1.3c.2 extends the second feedback pass from Q-only execution to native Q/K/V.
For every layer it performs K/V SGEMM, K-Norm, RoPE, device-side FP16 packing,
then appends that token after the 128 selected prompt tokens. Sparse attention
therefore runs over 129 tokens.

The sparse CUDA kernel was widened from 128 to 256 lanes with masked inactive
lanes. This supports a 128-token prompt budget plus a bounded decode tail while
preserving the old 128-token path.

## Five-run result

| Metric | Step 0 | Step 1 with current K/V |
|---|---:|---:|
| output token | 50 | 271 |
| chain median | 10.133116 ms | 10.781750 ms |
| LM-head median | 2.701644 ms | 2.695032 ms |
| native / teacher token | 50 / 50 | 271 / 271 |
| logit cosine | 0.999999999999905 | 0.999999999999911 |

The 28 layer token-KV record is 114,688 bytes (4,096 bytes per layer).
Device PTX `cvt.rn.f16.f32` packing has zero mismatches against host FP16
conversion across all 57,344 K/V values.

## Debugging history and boundary

The first device pack used `cuda_fp16.h`; NVRTC failed because this project
intentionally does not require a full toolkit include search path. Replacing it
with the PTX conversion instruction retained round-to-nearest FP16 behavior and
the runtime-only deployment contract.

This version includes the current token, but not an arbitrary multi-token
decode tail. The fixed prompt block plan is still used and no miss correction
is triggered by the new KV. The next version must persist these per-layer
records across steps and join a tail of length 1..32 to attention.
