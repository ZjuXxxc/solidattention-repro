# P1.2g/P1.2g.1: resident weights and cross-layer KV pipeline

This version separates two changes so their effects remain auditable.

- **P1.2g** preloads every FP32 tensor used by the 28-layer chain to VRAM.
  Preload is explicitly reported but excluded from the decode-region timer.
- **P1.2g.1** adds two registered pinned DRAM buffers, two VRAM KV slots, a
  CUDA copy stream and split liburing submit/collect. Layer L+1's SSD read is
  submitted before layer L compute. Once attention/post-norm finishes, the
  scheduler collects that read, starts H2D, and overlaps the copy with layer
  L's MLP.

The input fixtures, chain-selected blocks, FP16 KV representation and native
Qwen math are unchanged from P1.2f. This makes the timing comparison causal.

## Five-run results

| Metric | P1.2f streamed FP32 | P1.2g resident | P1.2g.1 pipelined |
|---|---:|---:|---:|
| timed 28-layer wall | 816.670344 ms | 20.410660 ms | **16.179101 ms** |
| resident preload, outside timer | 0 | 454.894207 ms | 453.136898 ms |
| resident weight bytes | 0 | 1,526,970,368 | 1,526,970,368 |
| selected-KV read sum | 15.524927 ms | 12.095031 ms | 19.553467 ms |
| selected-KV H2D sum | 0.914528 ms | 0.867296 ms | 0.762272 ms |
| exposed prefetch wait sum | n/a | n/a | **10.663527 ms** |
| max chain-output error | 9.1553e-5 | 9.1553e-5 | 9.1553e-5 |
| minimum output cosine | 1.0 | 1.0 | 1.0 |

P1.2g removes the artificial weight-streaming bottleneck and improves timed
wall by about 40x. P1.2g.1 improves the resident baseline by about 20.7%, but
does not hide all KV I/O. The first cross-layer prefetch is a roughly 7 ms
cold read in these independent process runs; steady small reads are roughly
0.15--0.25 ms while this 0.6B model's useful per-layer work is similarly tiny.
The sum of read durations is not a critical-path sum because reads overlap
compute; `exposed_prefetch_wait_ms` is the direct host-visible stall metric.

## Trace interpretation

`P1.2g.1-resident-fp32-kv-pipeline-trace.json` contains compute, liburing,
CUDA-copy and host-wait lanes. It is a scheduler reconstruction using measured
durations, not a CUPTI hardware trace. It intentionally shows the L/L+1
dependency and exposed wait. Layer 0 KV staging occurs before the timed region
and is omitted from this steady-state visualization.

## Reproduce

```bash
scripts/build_cpp_p1_2f.sh
.venv/bin/python scripts/run_cpp_p1_2f.py --resident-weights --repeats 5
.venv/bin/python scripts/run_cpp_p1_2f.py --resident-weights --pipeline-kv --repeats 5
```

## What this still does not claim

- The paper uses resident INT4 weights. P1.2g keeps exported FP32 tensors and
  therefore validates residency/scheduling, not its weight format or kernel.
- This is one fixed 28-layer prompt chain, not continuous 512-token decode.
  It does not yet predict the next token's selection or execute miss correction.
- The initial layer's KV stage is outside the timed region and is reported by
  its layer audit. End-to-end serving numbers must include startup separately.
- Attention remains the correctness-first native kernel rather than the
  paper's unreleased fused sparse CUDA/SYCL implementation.

The next version should use packed AWQ/INT4 weights and extend this exact
pipeline across continuous tokens, including selection correction and the
32-token tail-to-block lifecycle.
