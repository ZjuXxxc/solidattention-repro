# P1.2a: real Qwen3 layer CUDA parity

P1.2a replaces the synthetic compute windows with one complete real
`Qwen3-0.6B` transformer layer. This is a correctness checkpoint before that
layer executor is embedded in the P1.1 SSD pipeline.

Model provenance:

- checkpoint: `Qwen/Qwen3-0.6B`;
- revision: `c1899de289a04d12100db370d81485cdf75e47ca`;
- source weights: BF16;
- exported parity tensors: FP32;
- layer: 0;
- context: 128 real token embeddings, positions 384–511.

The exported model tensors remain under ignored `artifacts/qwen-layer0/`.
Weights are not committed. The repository contains only the exporter, native
executor, build scripts and small error metrics.

## Real operations executed

```text
embedding hidden states
 → input RMSNorm
 → Q/K/V projection (cuBLAS SGEMM)
 → per-head Q/K RMSNorm
 → RoPE
 → 16Q/8KV GQA stable-softmax attention
 → O projection (cuBLAS)
 → residual
 → post-attention RMSNorm
 → gate/up projection (cuBLAS)
 → SiLU(gate) × up
 → down projection (cuBLAS)
 → residual
```

CUDA kernels implement RMSNorm, head RMSNorm, RoPE, GQA attention, residual
addition and SwiGLU activation. Projection weights are the real layer-0
checkpoint weights.

## Teacher

`export_qwen_layer.py` loads tensors directly from safetensors and computes
every intermediate in PyTorch FP32. The native executable compares all major
boundaries, rather than only checking the final vector.

| Tensor | Maximum absolute error | Cosine |
|---|---:|---:|
| input RMSNorm | 4.77e-7 | 1.0 |
| post-RoPE query | 2.94715e-4 | 1.0 |
| post-RoPE key | 2.32637e-4 | 1.0 |
| value | 5.36e-7 | 1.0 |
| attended heads | 7.75e-7 | 1.0 |
| attention output | 5.36e-7 | 1.0 |
| post-attention residual | 5.36e-7 | 1.0 |
| post-attention RMSNorm | 1.431e-6 | 1.0 |
| gate projection | 3.338e-6 | 1.0 |
| up projection | 1.669e-6 | 1.0 |
| SwiGLU activation | 3.457e-6 | 1.0 |
| MLP output | 8.79e-7 | 1.0 |
| final layer output | **8.64e-7** | **1.0** |

Q/K have the largest pointwise difference because CPU and CUDA evaluate
`pow/sin/cos` for RoPE differently. The error does not amplify through
attention or the final layer output.

The recorded single execution wall is `5.086831 ms`. It includes a cold
correctness run and host-side synchronization, so it is not a steady-state
throughput result.

## Debugging record

1. The first native build failed because the cuBLAS wheel header includes
   `nv/target`, while the locally available CUDA header bundle omits CCCL.
   The implementation now declares only the stable cuBLAS v2 C ABI functions
   it calls and still links the official `libcublas.so.12`.
2. The first RoPE kernel read and wrote paired dimensions in place. Even though
   its observed output was close, that created a CUDA read/write race. The
   final kernel snapshots each 128-value head row into shared memory before
   writing rotated values.
3. Selection and CUDA attention initially used different queries during P1.1.
   P1.2a preserves the corrected contract: post-RoPE query, key and value are
   individually audited before attention.

## Remaining boundary

P1.2a proves one real dense layer. It does not yet read selected KV from SSD and
does not execute all 28 layers. P1.2b will replace the dense 128-token K/V input
with P1.1 selected/corrected KV blocks while retaining this layer executor and
teacher hidden-state audit.
