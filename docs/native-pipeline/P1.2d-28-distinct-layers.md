# P1.2d: 28 distinct real Qwen layer audit

P1.2d replaces P1.2c's layer-0 replica with all 28 distinct transformer layers
from Qwen3-0.6B. It uses bounded streaming: only one layer's FP32 export/native
weights need to be active at a time.

## Export layout

- 28 layer directories with different real weights and teacher tensors;
- one shared 56 MiB FP16 post-RoPE KV store;
- one 2 MiB KV segment per layer;
- per-layer KV byte offset in `manifest.json`;
- SHA-256 for every exported tensor;
- maximum layer bundle: 65,102,848 bytes;
- total layer bundles: 1,822,879,744 bytes.

The 1.8 GiB fixture is ignored by Git. Only code and audit metrics are
published.

## Teacher contract correction

The first full audit compared native FP16 SSD KV against a sparse teacher that
still used FP32 K/V. Layer 16 amplified this mismatch to a final point error of
`0.00288`, despite cosine `0.999999984`. The exporter now quantizes post-RoPE
K/V to FP16 first, then uses those exact values for:

1. InfLLM representative construction;
2. block selection;
3. sparse PyTorch teacher;
4. the native SSD store.

After aligning the contract, the worst native final error across all layers is
`6.1035e-5`.

The dense teacher is intentionally computed from the unquantized full 512-token
K/V. Sparse-vs-dense therefore remains an algorithm/quantization quality
metric, not implementation fidelity.

## Final 28-layer audit

| Metric | Result |
|---|---:|
| distinct layers audited | 28 |
| layers passing | 28/28 |
| maximum native-vs-sparse-teacher final error | **6.1035e-5** |
| minimum native-vs-sparse-teacher cosine | **1.0** |
| minimum sparse-vs-dense layer cosine | 0.990931404 |
| maximum sparse-vs-dense point error | 5.384328842 |
| shared FP16 KV store | 58,720,256 bytes |
| maximum active layer bundle on disk | 65,102,848 bytes |

Large sparse-vs-dense point error occurs on high-scale later-layer values; the
cosine is the more interpretable direction-quality measure. Every layer's raw
point errors and cosines remain in the published JSON.

## Selection limitation

For this deterministic sequential-token prompt, all 28 layers select
`[0,13,14,15]`; there is only one unique block set. The values are real native
InfLLM outputs, not hard-coded, but this prompt is not sufficiently diverse to
test selection variation. LongBench/WikiText prompts remain necessary.

## What is and is not chained

Each layer uses:

- its real dense-prefill hidden input;
- its own real weights;
- its own real post-RoPE FP16 KV segment and byte offset;
- its own sparse and dense teacher outputs.

The native audits are executed independently per layer so the first error can
be localized without upstream drift. P1.2d does **not** yet feed native sparse
layer `L` output into native layer `L+1`. That chained sparse decode, plus
per-layer persistent overlap in a single native process, is P1.2e.
