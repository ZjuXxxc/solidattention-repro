# P1.3c.0: native 28-layer hidden to next token

P1.3c.0 closes the output side of the native decode path. The final device
hidden state from the P1.2h depth-16 sparse chain is exported after its timer
and consumed by a native CUDA/cuBLAS head:

```text
28-layer sparse hidden -> final RMSNorm -> 151,936-way LM-head SGEMM -> argmax
```

The final norm and untied LM-head weights are exported as FP32 once. Weight
loading/H2D is outside the kernel timer, matching the resident-weight contract.

## Five-run result

| Metric | Result |
|---|---:|
| 28-layer chain median | 10.144562 ms |
| native LM-head median | 2.696542 ms |
| native / teacher argmax | **50 / 50** |
| native / teacher top-5 | **[50,35,38,271,198] / identical** |
| logit maximum error | 4.35114e-6 |
| logit mean error | 6.58269e-7 |
| logit cosine | 0.999999999999905 |

The first build attempt failed because reusing the Qwen kernel translation
unit indirectly includes `liburing.h`; the new target lacked the vendor include
path. Adding the same pinned liburing headers as the other native targets fixed
the dependency without changing computation.

## Boundary

This proves native hidden-to-token parity for one sparse decode position. It
does not yet feed token 50 through embedding lookup as the next iteration, nor
does it update that iteration's K/V tail. P1.3c.1 must close that feedback loop.
