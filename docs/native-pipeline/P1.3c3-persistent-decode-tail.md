# P1.3c.3: persistent 1–32 token decode tail

P1.3c.3 persists layer-major FP16 decode K/V between native token processes.
At each layer the chain copies the prior tail after the 128 selected prompt
tokens, projects and packs the current token after it, then runs attention over
`128 + prior_tail + 1` tokens. The resulting full tail is written for the next
iteration.

All steps have zero device-vs-host FP16 packing mismatches and native/teacher

## Capacity boundary

A separate scheduler-capacity test feeds 31 existing tokens per layer and
appends one current token. The CUDA kernel executes 160-token attention and
emits exactly 32 tokens per layer: 3,670,016 bytes across 28 layers, with zero
packing mismatches. The boundary fixture repeats valid prior K/V records, so it
tests memory/indexing capacity rather than language-model quality.
Its measured wall is `11.883292 ms`.

## Remaining lifecycle connection

The tail is now bounded by the CLI at 32 tokens, but P1.3c.3 does not yet invoke
P1.3b's seal operation online. The next step must atomically seal tail=32 into
the main store, generate representatives, increment selection generation, and
begin the next iteration with an empty/new local segment under the chosen
local-window policy.
