# P1.2h: bounded multi-layer SSD read-ahead

P1.2h replaces the unbounded P1.2g.3 DRAM upper bound with a configurable
window. Each window slot owns one 512 KiB registered pinned host buffer and one
independent liburing ring with one selected-block batch outstanding. The layer
generation is implied by the circular slot index.

The accelerator still uses only two VRAM KV slots. At layer L, the host slot
that has just been consumed can submit L+depth. After attention/post-norm, the
scheduler collects L+1 and starts its H2D on the copy stream while L's MLP runs.

## Five-run depth scan

| Read-ahead depth | Pinned DRAM | Decode wall | Exposed wait | Final error |
|---:|---:|---:|---:|---:|
| 1 (P1.2g.2) | 1 MiB | 15.095921 ms | 10.328627 ms | 9.1553e-5 |
| 2 | 1 MiB | 13.430375 ms | 5.830500 ms | 9.1553e-5 |
| 4 | 2 MiB | 12.880146 ms | 5.337566 ms | 9.1553e-5 |
| 8 | 4 MiB | 12.181188 ms | 4.722187 ms | 9.1553e-5 |
| 16 | 8 MiB | **10.167049 ms** | **2.910755 ms** | 9.1553e-5 |
| all 28 (P1.2g.3 upper bound) | 14 MiB | 7.197472 ms | 0 ms | 9.1553e-5 |

The `kv_read_ms` field measures submit-to-collection lifetime. With deeper
read-ahead, a completed request intentionally remains outstanding until its
consumer layer arrives, so summing these lifetimes is meaningless and can
reach seconds. It is not SSD service time. `total_wall_ms` and
`exposed_prefetch_wait_ms` are the critical-path metrics.

## Debugging history

The first depth-4 implementation crashed with `SIGSEGV` in
`UringReader::submit_blocks_fixed`. GDB showed a null depth-1 reader at the
tail of the layer loop. When no new L+depth request remained, an overly broad
`else if` incorrectly fell through to the depth-1 submission branch. Restricting
that branch to `read_ahead == 1` fixed the scheduler.

The cleanup path was also corrected: all liburing rings now unregister their
fixed buffers before `cudaFreeHost` releases the pinned allocations.

## Reproduce

```bash
scripts/build_cpp_p1_2f.sh
for depth in 2 4 8 16; do
  .venv/bin/python scripts/run_cpp_p1_2f.py \
    --resident-weights --pipeline-kv --final-audit-only \
    --read-ahead "$depth" --repeats 5
done
```

## Remaining boundary

This remains a fixed one-token, 28-layer chain. The next scheduler step is to
reuse the window across continuous decode tokens, attach selection generations
to every slot, and overwrite only history-prediction misses. Packed INT4/AWQ
weights remain a separate version so scheduling and quantization errors are not
conflated.
