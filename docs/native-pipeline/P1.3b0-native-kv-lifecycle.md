# P1.3b.0: native bounded decode-KV lifecycle

This checkpoint moves the V12 lifecycle contract into C++ before wiring real
Qwen K/V projection into it. Each of 28 layers owns a token-major FP16 tail,
query-head score accumulators and a monotonic selection generation.

When `tail >= local(32) + block(32)`, the oldest complete block is sealed:

1. select four representative indices independently for every query head;
2. write the actual 128 KiB interleaved K/V block into that layer's reserved
   region of the main store with `O_DIRECT`;
3. increment the selection generation;
4. remove exactly 32 old tokens while retaining the local window;
5. read every new block back through registered-buffer liburing and compare all
   bytes with the expected block.

## Five-run 512-token result

| Metric | Result |
|---|---:|
| layers / output tokens | 28 / 512 |
| sealed blocks | 448 (16 per layer) |
| verified main-store reads | 448 / 448 |
| representative head audits | 7,168 |
| final resident tail | 32 tokens per layer |
| final selection generation | 16 per layer |
| store allocation | 121,110,528 bytes |
| lifecycle + full verification wall, median | 184.903618 ms |

The 31-token boundary test seals zero blocks and retains 63 tokens; the next
token seals one block and returns to 32. Thus partial tails are neither lost nor
prematurely written.

## Scope

The physical layout, O_DIRECT write, liburing readback, bounded tail and
generation transition are native and real. The FP16 bit patterns are
deterministic test data, not yet produced by Qwen K/V projections. This is named
P1.3b.0 rather than P1.3b to preserve that distinction.

The wall measurement includes all 448 verification reads and is not a decode
latency claim.

```bash
./scripts/run_cpp_p1_3b0.sh --tokens 512
.venv/bin/python scripts/benchmark_cpp_p1_3b0.py
```
