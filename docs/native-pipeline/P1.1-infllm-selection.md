# P1.1: InfLLM selection inside the correction pipeline

P1.1 replaces P1.0's controlled oracle sequence with the shared C2.1 native
InfLLM selector. It is the first native version in which the same per-layer
query drives both block selection and CUDA sparse attention.

## Selection construction

The fixture contains finite FP16 K/V, not arbitrary byte patterns:

- 512 prompt tokens, 16 query heads, 8 KV heads, head dimension 128;
- 32-token blocks, 16 blocks total;
- local-causal representative scoring with `local_window=32`;
- `repr_topk=4`, retained independently for every query head;
- one init block, one local block and two score-selected dynamic blocks.

The complete 512-token K/V tensor is repeated across 28 SSD layers. Queries use
different prompt positions by decode step and layer. `select_shared_blocks()`
therefore runs for every layer execution, and its result becomes both:

1. the current oracle set used to audit the history prediction and correction;
2. the exact KV set consumed by the CUDA attention kernel.

## Two different correctness questions

P1.1 deliberately reports two recalls:

- `corrected_oracle_block_recall=1`: physical correction made resident KV
  exactly equal to the native selector's requested blocks;
- `dense_oracle_block_recall=0.809152`: the representative selector chose
  80.92% of the four blocks selected by exact dense block attention mass.

History hit rate is a third, separate metric. It only describes reuse from the
previous decode step and says nothing about dense attention quality.

Dense teacher auditing computes stable-softmax attention over all 512 tokens
for every measured step/layer/query head. At a 25% token budget, the selected
blocks contain 26.4404% of dense attention mass on this synthetic fixture.
This weak separation is a fixture/selection result, not hidden by the perfect
physical correction score.

## Formal result

RTX 4080 Laptop, 10 independent repeats, 16 steps × 28 layers:

| Metric | Result |
|---|---:|
| representative build, median | 52.199527 ms |
| native selection / repeat, median | 9.773652 ms |
| history block hit rate | 58.5938% |
| miss blocks / repeat | 742 / 1792 |
| corrected selector-block recall | **100%** |
| dense-oracle block recall | 80.9152% |
| selected dense attention mass | 26.4404% |
| serial layer latency, median | 0.314362 ms |
| corrected pipeline layer latency, median | 0.374102 ms |
| speedup, median (P10–P90) | **0.849826×** (0.795492–0.870508×) |
| correction SSD read / repeat, median | 47.289846 ms |
| correction H2D / repeat, median | 5.521952 ms |
| serial vs pipeline max error | **0** |

P1.1 is a measured negative result. The query sequence changes enough that
previous-token selection predicts only 58.59% of blocks. Reading and overwriting
742 miss blocks costs more than P0's overlap saves. This is the expected system
consequence of a weak history predictor, and it explains why history stability
must never be presented as selection quality.

## Important correction made during implementation

The first P1.1 short run used varying queries for selection but retained P0's
fixed query in CUDA attention. The resident set was physically correct but did
not describe the attention being executed. The final implementation updates
the CUDA query on the compute stream before the QKV window and attention.
Published metrics were generated only after this fix.

## Trace lanes

`P1.1-infllm-history-correction-trace.json` exposes:

- predicted next-layer SSD read and H2D;
- native selection correction SSD read;
- partial correction H2D overwrite;
- current query/QKV window;
- corrected sparse attention;
- current FFN and next-layer H2D overlap;
- correction and cross-layer barriers.

## Remaining boundary

Representative construction and selection are now the C2.1 InfLLM design, and
the attention is a real CUDA GQA kernel. QKV and FFN remain synthetic scheduling
windows; the K/V fixture is not a Qwen checkpoint. P1.2 must replace those
windows with exported real Qwen layer tensors and compare hidden states/logits
against the PyTorch teacher.
