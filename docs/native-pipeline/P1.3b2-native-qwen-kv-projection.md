# P1.3b.2: native Qwen K/V projection into the lifecycle

P1.3b.2 removes the PyTorch projection dependency from the lifecycle input.
For all 28 Qwen3-0.6B layers and 512 real hidden-state tokens, the existing
native CUDA/cuBLAS executor performs:

```text
RMSNorm -> K/V SGEMM -> K-Norm -> RoPE(K) -> FP16 token-major packing
```

The resulting 29,360,128 FP16 elements are compared with the PyTorch-exported
teacher store, then used as the source for the native seal/write/readback path.

## Projection parity

| Metric | Result |
|---|---:|
| FP16 elements | 29,360,128 |
| bit-exact elements | 99.857858% |
| mismatch rate | 0.142142% |
| mean absolute error | 2.9334e-7 |
| maximum absolute error | 0.0625 |
| cosine | 0.999999999987 |

Bit identity is not claimed. cuBLAS FP32 reduction and the PyTorch teacher can
round values on opposite sides of an FP16 boundary. The aggregate cosine and
mean error show numerical parity; per-layer records remain in the metrics so a
single bad layer cannot be hidden.
The largest absolute error occurs in layer 5; that layer's mismatch rate is
0.144005%, mean absolute error is `3.7590e-7`, and maximum is `0.0625`.

## Lifecycle result

The 512 projected tokens are split into 32 initial-local tokens plus 480 decode
tokens. Each layer seals 15 blocks:

| Metric | Result |
|---|---:|
| sealed / byte-verified blocks | 420 / 420 |
| final local tail | 32 tokens/layer |
| final selection generation | 15/layer |
| five-run lifecycle + verification median | 156.113445 ms |

This now proves native K/V projection-to-main-store continuity. It still uses
pre-exported real hidden states and does not yet run logits-driven token choice.

```bash
.venv/bin/python scripts/run_cpp_p1_3b2.py
```
