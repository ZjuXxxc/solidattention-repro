# C1.2 — Persistent device resources and wall-clock audit

C1.2 keeps the C1.1 parallel attention kernel unchanged. It adds a host
wall-clock measurement around the complete backend call and removes reusable
resource creation from that call.

## Resource lifetime changes

CUDA C1.1 already retained KV/query/output device buffers through
`ensure_attention_capacity()`. C1.2 additionally creates four timing events
once with the backend and re-records them on every invocation.

SYCL C1.1 allocated and freed KV, query and output USM buffers for every
attention operation. C1.2 grows three persistent buffers on demand and releases
them only in the backend destructor.

One unmeasured warmup operation initializes the runtime/JIT and persistent
resources before every measured run. Metrics explicitly store
`warmup_operations=1`.

## Three-run paired result

64 measured operations per run. Values are mean ± sample standard deviation.

| Backend/version | Complete backend wall time | H2D/USM | Kernel | D2H |
|---|---:|---:|---:|---:|
| CUDA C1.1 | 0.092245 ± 0.000124 ms | 0.037183 ms | 0.040104 ms | 0.008309 ms |
| CUDA C1.2 | 0.090433 ± 0.000206 ms | 0.036867 ms | 0.040025 ms | 0.007989 ms |
| SYCL CPU C1.1 | 0.468826 ± 0.049722 ms | 0.232898 ms | 0.065140 ms | 0.023500 ms |
| SYCL CPU C1.2 | 0.229556 ± 0.016728 ms | 0.078964 ms | 0.055202 ms | 0.018361 ms |

CUDA improves only 1.96% because its expensive buffers were already
persistent; this isolates the small event-creation cost. SYCL improves 2.04x
and reduces wall time by 51.04%. Its measured copy event also falls by 66.10%,
consistent with avoiding first-touch/mapping work on newly allocated USM.

All 12 paired runs retain max absolute error `2.6077e-8` and cosine `1.0`.

## Interpretation

Device event timings alone understated the SYCL problem: the short eight-run
smoke initially showed about 19 ms mean host wall time because runtime/JIT
startup was included, while the device kernel event was below 0.1 ms. The
explicit warmup separates startup from steady state, and the new wall metric
then exposes per-call allocation/submission overhead that device profiling
events cannot see.

C1.2 still performs a correctness D2H after every call and allocates the host
`std::vector<float>` result. A decode implementation should keep attention
output on device and feed it directly into `o_proj`.

## Next boundary

C1.3 should remove audit D2H from the performance path, retain a sampled audit
mode, and prototype online softmax. C2 then consumes real Qwen blocks and
InfLLM representatives before the cross-layer scheduler is introduced.
