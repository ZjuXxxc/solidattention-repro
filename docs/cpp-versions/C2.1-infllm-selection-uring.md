# C2.0/C2.1 — InfLLM selection and batched liburing packing

C2 moves the native line from a fixed selected buffer to a real selection and
storage path:

```text
prompt Q/K
  → local-causal received attention mass
  → per-query-head, per-block top-4 key mean
  → mean query-head block score + init/local constraints
  → one liburing submission with four fixed-buffer reads
  → contiguous 512 KiB selected KV
  → CUDA/SYCL GQA attention
```

## C2.0 retained failed representative

The first transport smoke used four fixed token offsets inside every block and
averaged their keys. It selected blocks `[0, 3, 8, 15]`. Storage packing and
device attention were correct, but selected-vs-dense output cosine was only
`0.456345`.

This reproduces the failure mode found in Python V9: a stable transport path
does not validate representative quality. C2.0 was a preliminary single run
and was not published as an immutable headline artifact.

## C2.1 InfLLM-style representative

C2.1 generates a deterministic 512-token synthetic prompt Q/K and implements
the same dataflow as Python V11:

1. for every prompt query, attend only to its causal 32-token local window;
2. accumulate the probability mass received by every key, separately for each
   query head;
3. select the four highest-mass tokens inside every 32-token block;
4. average their expanded GQA keys to form a query-head representative;
5. retain per-head dot products until the final mean block score.

Init block 0 and local block 15 are mandatory. Two dynamic blocks complete the
four-block budget. CUDA and SYCL independently select `[0, 8, 13, 15]`.

Selected-vs-dense cosine improves from C2.0's `0.456345` to `0.987693`.

## liburing packing

`read_blocks_fixed()` submits all four 128 KiB reads before waiting for CQEs.
Each SQE targets a different 128 KiB region of one registered 512 KiB pinned
buffer, so completion produces the token-major packed input required by the
attention kernel without concatenating Python bytes.

Every formal run compares each packed slot with its original full-store block.
All are bit-exact.

## Three-run result

| Stage | CUDA host/device | SYCL CPU host/device |
|---|---:|---:|
| representative build | 51.5494 ± 0.0348 ms | 47.9855 ± 0.8631 ms |
| per-token block selection | 0.014579 ± 0.000305 ms | 0.010712 ± 0.000878 ms |
| four-request liburing batch | 0.193863 ± 0.034349 ms | 0.206934 ± 0.039149 ms |
| selected KV H2D/USM | 0.031392 ± 0.006317 ms | 0.180954 ± 0.081605 ms |
| sparse attention | 0.039936 ± 0.000000 ms | 0.074857 ± 0.033916 ms |

The scalar CPU representative build is a prefill/offline cost, not a per-token
decode cost. SYCL copy/kernel variance is retained in the standard deviation.
All six runs also produce the same representative-token offset hash
`7873450381430813043`.

Both backends have max error `7.45e-8` and cosine `1.0` against the packed
sparse CPU oracle.

## Current reproduction boundary

C2.1 correctly reproduces the representative algorithm, shared selection
policy, batched SSD packing and accelerator attention contract, but the prompt
Q/K is synthetic. It therefore validates system mechanics and numerical
consistency, not model accuracy.

C3 must export real Qwen post-RoPE Q, FP16 KV and V11 representatives using a
versioned binary manifest, then make this same C++ selector reproduce Python
block IDs and teacher-forced attention mass layer by layer.
