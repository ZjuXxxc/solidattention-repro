# C1.1 — Parallel CUDA block and SYCL work-group attention

C1.1 keeps C1's storage, dtype, GQA mapping and CPU oracle unchanged. Only the
device work decomposition changes.

## Kernel mapping

```text
one query head
  └─ one CUDA block / SYCL work-group (128 lanes)
       ├─ lane t: dot(query, key[t]) for one selected token
       ├─ group maximum reduction
       ├─ exp(logit - maximum) and group sum reduction
       └─ lane d: weighted sum of value[:, d] for one output dimension
```

The 128 probabilities live in CUDA shared memory or SYCL local memory. C1 used
one serial thread/work-item per query head; C1.1 exposes both the token and
output-dimension axes while retaining an auditable two-pass stable softmax.

## Three-run paired result

64 attention operations per run, 128 selected tokens, FP16 K/V, FP32
accumulation. Values are mean ± sample standard deviation across three runs.

| Backend/version | Kernel | Read+H2D+kernel+D2H stage sum |
|---|---:|---:|
| CUDA C1 serial | 2.178537 ± 0.065752 ms | 2.380465 ± 0.065186 ms |
| CUDA C1.1 parallel | 0.039970 ± 0.000016 ms | 0.225097 ± 0.005717 ms |
| SYCL CPU C1 serial | 0.420021 ± 0.011418 ms | 0.898791 ± 0.012770 ms |
| SYCL CPU C1.1 parallel | 0.070215 ± 0.005198 ms | 0.615237 ± 0.044755 ms |

CUDA kernel speedup is 54.50x and the measured stage sum improves 10.58x.
SYCL CPU kernel speedup is 5.98x and stage sum improves 1.46x.

Both optimized backends report max absolute error `2.6077e-8` and cosine `1.0`
against the C++ CPU oracle in every run.


## What the stage sum excludes

The stage sum adds the individually instrumented fixed read, device copy,
kernel and correctness D2H durations. It is not end-to-end decode latency:

- device allocation/free and CUDA/SYCL API overhead are outside event ranges;
- query projection, RoPE, output projection, residual and FFN are absent;
- fixed block selection avoids representative scoring and correction;
- SSD, H2D and attention are still serial rather than cross-layer pipelined.

This distinction matters more for SYCL because the current backend allocates
three USM buffers for every attention call.

## Remaining optimization work

- Replace the two-pass probability materialization with online softmax.
- Reuse all device allocations and events.
- Vectorize FP16 loads and use warp/sub-group shuffles where profitable.
- Test more than 128 selected tokens without hard-coded local arrays.
- Run the SYCL kernel on the RTX 4080 after installing the Codeplay plugin.
- Feed real selected Qwen KV blocks and compare against the Python dense audit.
