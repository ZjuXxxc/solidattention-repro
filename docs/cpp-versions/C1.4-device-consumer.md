# C1.4 — Device-side attention output consumer

C1.4 proves that the device-resident output introduced in C1.3 can be consumed
by a downstream kernel in the same CUDA stream or SYCL dependency graph.

## Consumer definition

The consumer reads all 2,048 FP32 attention output elements and computes:

```text
checksum = Σ output[i] × (1 + (i mod 17) × 0.001)
```

It is intentionally simple and serial so the dependency and CPU reference are
easy to audit. It is **not** an output projection or a performance kernel.
Non-audit operations keep the checksum on device. Five sampled operations per
64-run copy only the four-byte checksum to the host.

## Dependency graph

```text
H2D KV/query → parallel GQA attention → output consumer → optional 4-byte D2H
```

CUDA launches both kernels on one non-blocking stream. SYCL submits the
consumer with an explicit dependency on the attention event, and the sampled
copy depends on the consumer event.

## Three-run result

| Backend | Attention | Consumer | Complete backend wall | Max checksum error |
|---|---:|---:|---:|---:|
| CUDA | 0.040183 ± 0.000275 ms | 0.024496 ± 0.000021 ms | 0.108761 ± 0.000514 ms | 5.72e-6 |
| SYCL CPU | 0.057553 ± 0.001752 ms | 0.007418 ± 0.000495 ms | 0.235857 ± 0.007578 ms | 2.86e-6 |

All sampled checksum comparisons have cosine `1.0`.

Compared with C1.3, CUDA wall time rises by 0.024636 ms (29.29%), nearly equal
to its measured consumer duration. SYCL wall time rises by 0.043916 ms
(22.88%) even though the consumer device event is only 0.007418 ms. The gap is
additional queue submission, dependency and host wait overhead.

This retained negative delta is useful: a downstream dependency is not free,
and device event duration alone understates the SYCL control-plane cost.

## Failed first SYCL build

The first build bound the selected completion event to `const sycl::event&`.
oneAPI 2026.1.1 exposes a non-const `event.wait()`, so compilation failed.
Changing completion to an owned mutable `sycl::event` fixed the build. The
terminal printed an older C1.3 metrics file after that failure, but no artifact
was copied; the formal runner validates `version=C1.4`.

## Next step

C1.5 should replace this scalar consumer with a small tiled output projection.
That version must separate GEMM time from queue/control time and keep the
projected output device-resident. Online softmax remains a separate attention
kernel experiment.
